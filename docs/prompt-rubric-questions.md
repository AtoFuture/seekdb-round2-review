# Agent prompt 评审：学生证据补强清单

2026-11-12。背景：平台对 `aea69813` 的正式反馈是「Prompt 结果无效、待复核、超出平台 0–100 范围或缺少材料摘要，本项不参与排名」。
按现行规则 `agent-learning-evidence-v3-unbounded`，任一维度证据不足就会让整份材料进入 NEEDS_REVIEW，原始分为 null，直接不计分。
所以这一项不是“材料不好看”，而是**有一个维度缺学生自己的证据，整表作废**。

## 现在材料里已经补上的结构

`agent/conversation.json` 新增 `rubric_instances`：12 个独立实例，每个只归属一个维度，并分别给出
`student_evidence`（学生原话，JSON pointer 可定位）、`result_evidence`（实际结果，pointer 可定位）、
`scoring_rationale`（为什么算这一档）与 `attribution_limit`（哪部分是学生、哪部分是 Agent）。
五个维度现在都有实例：问题理解与自主拆解 3 个、技术理解与迁移 2 个、独立验证与质疑 3 个、实验与反馈迭代 2 个、取舍与反思 2 个。

同时恢复了归档里带“假设→反证→修正”结构的观察记录（a01–a05、a14、a19、a22、a26、a27、a30、a34、a35、a39）

并在 `summary` 里说明平台的 E 是性能原始口径数值、不是 0–100 制分数，避免被读成“超出范围”。

### 技术理解与迁移

1. **协议形态**：官方改成 stdin/stdout 的 JSONL 之后，你是怎么判断“容器里跑的那个进程就是被驱动的那个程序”的？
   （可引用：你转述的“按 docker 正常规则给主业务程序发 stdin”，以及你后来追问的 `agent/conversation.json` 路径问题）
2. **距离语义**：为什么 TopK 的并列要按主键升序、而且要先 sqrt 再排序？中间哪一步如果做错会直接判 0？
3. **double 累加顺序**：为什么实现里坚持“每个候选按维度顺序用 double 累加、不用 FMA、不改结合顺序”？
   如果改成 float32 或横向归约会发生什么？
4. **转置与分块**：为什么把 16 个候选按维度转置后一起算，比一行一行算更快，而且为什么这个转置布局**最终没有合入生产**？

### 取舍与反思

5. **写入放大**：这一版把写入路径改成“压缩 radix 层级 + 位图编码稀疏节点”，你用什么判断它值得做？
   代价是什么（兼容旧文件、失去哪些能力）？
6. **缓存预算**：为什么数值列缓存与原始行快照要**共用** 8 MiB 预算而不是各占 8 MiB？超预算时为什么必须回退而不是截断？
7. **提交策略**：为什么把提交策略从 Ordered（先同步数据再写根再同步）改成 ProcessCrash（写完根再统一一次 fsync）？
   这个取舍放弃了哪种保证？
8. **失败记录的价值**：这一轮有几次优化被否掉了（转置布局、AVX2 gather、AVX-512 逐位检查、链接期优化）。
   哪一次最值得保留为“负面结果”，为什么？

## 写作要求（避免被判成编造）
